# Pi capability analysis for Botashka

This is a primary-source analysis of the local Pi checkout. It separates reusable interaction and runtime ideas from Pi's TypeScript/Node-specific product surface.

## Principal packages

Pi is a TypeScript monorepo whose user-facing product is `@earendil-works/pi-coding-agent`; it layers on independently packaged runtime capabilities rather than putting all behavior in the CLI. The repository's package table identifies `pi-ai` (multi-provider LLM API), `pi-agent-core` (tool-calling/state runtime), `pi-coding-agent` (interactive coding CLI), `pi-tui`, `pi-durable`, `pi-telemetry`, and `chord`; the workspace build also includes `pi-codemode`, `pi-mcp`, and `pi-env`. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/README.md:72-86`; `/Users/I067908/Documents/code/ai-ref/pi/package.json:5-17`.)

| Pi package/layer | Responsibility | Botashka relevance |

## Coding-agent user workflow

Pi starts in the working directory; that directory scopes file/instruction/config discovery and default saved-session grouping. The user authenticates with `/login` and submits a task. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/README.md:45-53`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:1-13`.) Its terminal transcript exposes prompts, responses, tool calls, results, and errors; status reports directory, session, model, context use, usage, and cost. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:7-10`.)

Useful interaction details are deliberate rather than cosmetic: `Enter` sends a prompt, `Alt+Enter` queues work after the current task, a normal in-flight message steers the next model response after the current turn/tool calls, and `Escape` aborts and returns queued messages to the editor. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:29-40`.) Users can switch model and thinking level, start/resume/name/inspect sessions, branch with `/tree`, `/fork`, or `/clone`, and compact history. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:44-66`.) A `!command` runs a local shell command and supplies output to the conversation; `!!command` omits it from model context. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:68-76`.)

Pi intentionally does **not** confirm every tool call; its documentation tells the user to review commands and changed files and to sandbox untrusted or unattended work. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:21-27`.)

## Agent loop, state, model, and tool runtime

Pi's documented loop is compact: append the submitted message to the active branch; assemble system prompt, branch history, tool definitions, and model settings; stream the provider response; record it; execute and record tool results; issue another request only when tool results or queued messages require one. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/how-pi-works.md:7-13`.)

The implementation keeps `AgentMessage` objects through the loop and converts them to provider `Message[]` only at the LLM boundary. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent-loop.ts:1-4`.) `Agent` owns the current transcript, lifecycle events, tool execution, and separate steering/follow-up queues; default queue mode is one message at a time and default tool execution is parallel. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent.ts:149-180`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent.ts:188-203`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent.ts:238-262`.) Tool calls may run sequentially or in parallel, and before/after hooks can block a call, transform its result, or request batch termination. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/types.ts:39-47`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/types.ts:60-103`.)

The loop has explicit request/turn seams: `prepareRequest` can replace context, model, or thinking level before every provider call, while `prepareNextTurn` can do the same before the next turn. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/types.ts:160-189`.) Provider failures are part of the returned event stream rather than thrown from the stream function contract. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/types.ts:19-37`.)

**Botashka implication:** represent the durable transcript and explicit run status as data, run tools behind a small capability map, and make the model-call boundary the sole place that knows a provider wire format. The evidence above supports this as the smallest useful extraction of Pi's design; it does not require copying its TypeScript event hierarchy. (Inference from `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent-loop.ts:172-281`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent.ts:188-262`.)

## Code mode and tool creation

Pi's ordinary extensibility path is an in-process TypeScript extension. Extensions can register LLM-callable tools, commands, event handlers, UI, renderers, providers, MCP servers, and restart-surviving state; project-local extensions load only after project trust. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/extensions.md:3-19`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/extensions.md:123-153`.)

`codemode` is a second mechanism: the model sends raw JavaScript that runs as an async function in a QuickJS sandbox with no Node APIs, filesystem, network, or timers. It can call injected tools and non-chat models; only script output returns to the model, enabling parallel calls and filtering before context growth. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:1-18`.) Tool discovery is deliberately dynamic: scripts can query `ALL_TOOLS`, search by relevance, and fetch individual declarations, which keeps large/MCP tool sets out of the initial prompt. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:20-35`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:48-52`.) Its session-persisted key/value store commits only on successful scripts and is branch-relative. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:54-58`.)

The sandbox is capability-limited, not magically safe: injected tools remain the route to external effects, and cancelled tool calls are not undone. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/codemode/README.md:47-62`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:15-18`.)

## Extensions, MCP, and session persistence

Pi resolves project trust before loading project settings/resources and runs enabled tools with the OS permissions of the Pi process. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/how-pi-works.md:47-49`.) Extensions therefore run with full process permissions and can inspect prompts, files, credentials, and session history. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/extensions.md:3-9`.)

MCP servers are configured at user scope (`~/.pi/agent/mcp.json`) or, after trust, project scope (`.pi/mcp.json`), and support stdio plus streamable HTTP. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/mcp.md:1-32`.) MCP tools can be direct, deferred through tool search, available only through codemode (the default), or hidden; this is Pi's prompt-size and tool-discovery control. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/mcp.md:191-202`.)

Sessions are append-only JSONL trees: entries have IDs and parent IDs, the current leaf selects the active branch, and compaction replaces older material only in reconstructed model context while retaining original entries. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/how-pi-works.md:25-31`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/session-format.md:1-5`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/session-format.md:123-147`.) They are automatically saved by default beneath `~/.pi/agent/sessions/`, grouped by working directory; `--no-session` is explicitly ephemeral. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/sessions.md:5-18`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/sessions.md:48-54`.)

## Tests and evals

Pi runs ordinary workspace tests and additionally exposes an MCP conformance test command. (Source: `/Users/I067908/Documents/code/ai-ref/pi/package.json:40-42`.) The coding-agent package and agent core each use Vitest, with agent-loop, agent, and end-to-end tests visible in their local test directories. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/package.json:31-41`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/package.json:1`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/test/agent-loop.test.ts:1`.)

Its dedicated eval package uses `vitest-evals`: host smoke tests, an explicit documentation audit, and Docker-isolated paired `without_docs`/`with_docs` documentation-lift comparisons. It plans each case/variant/model/run combination, runs every arm in a fresh container, and withholds headline lift when any pair is blocked. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/evals/README.md:1-20`; `/Users/I067908/Documents/code/ai-ref/pi/packages/evals/README.md:71-105`.)

## Recommendations for a small, single-user Clojure/Babashka Botashka

### Adopt now

- **A simple visible transcript plus streaming event log:** show user text, assistant text, tool starts/results/errors, current model, and cancellation state. Pi demonstrates that this makes autonomous local work inspectable. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:7-10`; inference: implement with Botashka's existing terminal conventions.)
- **A data-first loop:** transcript → provider request → streamed assistant message → validated tool calls → tool results → repeat. Keep provider conversion at one boundary and tool execution behind a small registry. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/how-pi-works.md:7-23`; `/Users/I067908/Documents/code/ai-ref/pi/packages/agent/src/agent-loop.ts:1-4`.)
- **Explicit interruption/queue semantics:** support stop, one pending steering message, and one follow-up queue before adding richer UI controls. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:29-40`.)
- **Append-only local JSONL session records:** start linear, include message/tool/model metadata, and make compaction a new summary record rather than destructive rewriting. Pi's tree is valuable evidence for preserving history, but a linear first version meets single-user needs. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/session-format.md:1-5`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/session-format.md:123-147`.)
- **Deterministic tests around loop transitions and tool validation before LLM evals.** Pi keeps conventional tests alongside behavioral evals. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/package.json:40-42`; `/Users/I067908/Documents/code/ai-ref/pi/packages/evals/README.md:109-129`.)

### Defer

- **MCP client support, OAuth, and tool-exposure policies:** useful interoperability, but only after Botashka has a stable native tool protocol and a real MCP-server requirement. Pi's MCP surface includes user/project config, remote auth, background connections, and several exposure modes. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/mcp.md:30-100`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/mcp.md:191-202`.)
- **Branching/forking session trees and automated LLM compaction:** retain the append-only format and add these only when users need parallel explorations or context pressure makes summaries necessary. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/sessions.md:20-46`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/session-format.md:123-162`.)
- **Codemode/model-written orchestration:** it solves parallel fan-out, tool discovery, and context filtering, but adds a second language/runtime, sandbox lifecycle, memory/time limits, and cancellation caveats. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:1-18`; `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/codemode.md:224-230`.)
- **Docker-based comparative LLM evals:** adopt a small task corpus and repeatable manual/provider checks first; Pi's paired-container system is justified for a mature documentation/product evaluation program. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/evals/README.md:71-105`.)

### Do not copy

- **Pi's broad package topology, TUI framework, RPC surface, telemetry, durable runtime, and plugin host:** these support a general distributable TypeScript platform, not a small single-user Babashka tool. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/README.md:72-86`; `/Users/I067908/Documents/code/ai-ref/pi/package.json:16-17`.)
- **Unrestricted in-process extension execution as Botashka's default:** Pi explicitly gives extensions the process's permissions and relies on trust. Prefer a fixed native tool registry and explicit confirmation/policy for any destructive Botashka tools. (Sources: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/extensions.md:3-9`; `/Users/I067908/Documents/code/ai-ref/pi/README.md:88-96`.)
- **The “no confirmation for every tool call” default:** it is acceptable only when users deliberately accept Pi's OS-level trust model. For Botashka, retain user control around writes and process execution unless an explicit unattended mode is added. (Source: `/Users/I067908/Documents/code/ai-ref/pi/packages/coding-agent/docs/usage.md:21-27`; inference from the single-user safety goal.)
